# 05 · 本地资源功能检查

版本：v0.0 · 当前已有实现和资源，以实际产物为准。本轮检查资源能否支持功能，不进行审查任务。

## 1. 资源与用户输入

航班信息由用户提供；机场、航司、联盟、机型、Logo、字体、自然色地球与标签是本地参考资源。不要求查询航班真实性，不补全球历史数据库。

检查起步目录能否搜索/选择、自定义资料能否新增修改、机场坐标是否用于正确端点、缺定位是否保留记录、个人覆盖是否被正确保存。资源数量与覆盖范围如实列出，不要求全世界目录齐全。

## 2. Logo 和字体

实际已有SVG应正常显示，比例正确，用户导入/替换后可保存并重新打开。缺Logo允许清楚的占位；某个联盟标志未提供可列补齐建议，不自动阻断主要功能。查看高DPI清晰度和浅深主题效果时记录实际环境，完整品牌或显示矩阵可留后续。

当前实现记录列出Lufthansa、Star Alliance与oneworld已有SVG，SkyTeam暂缺。新验收Agent需确认实际显示和导入行为，不直接继承自测结果，也不为补齐某个标志扩大验收范围。

默认Inter与系统fallback的实际显示、本地资源加载和英语UI是功能检查点。

## 3. 地球与标签

当前实现采用CesiumJS与本地4K/2K自然色晕渲图。检查能否启动、旋转、缩放、显示机场/路线、适配总览和选中记录；纹理清晰尺度与限制如实说明。真实高程、街道或建筑模型不属于首版必需能力。

只检查实际可用的标签与图层显示/开关。缺少政治边界图层不作为本轮阻断问题，不进行相关标准或来源审查。地图端点与线路几何仍需功能验证，不能以整体图像漂亮代替路线正确性。

## 4. 个人资源与备份

使用正常本地SVG、个人资料和约定格式的底图测试导入；检查预览、确认、取消、替换、重启、导出和恢复。旧记录引用的资源不应因资料更新突然消失。

参考manifest和交付清单确认文件齐全、版本对应、程序能加载；不做路径安全测试。正常备份恢复应保留个人资料、已有Logo和设置，导出内容是否足够重新使用是本轮重点。

## 5. 改进建议

起步目录丰富度、缺失品牌、纹理清晰度、标签密度、全部底图格式和资源管理便捷性按实际体验提出建议。报告区分功能bug、资源不足和产品增强，不把有限覆盖直接等同基本功能失败。
