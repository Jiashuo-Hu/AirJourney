# 09 · v0.0 当前验收决策

日期：2026-10-10 · 版本保持v0.0。本页按负责人最新指示更新，优先于历史审查要求。

## 当前目标

独立判断AirJourney的基本功能是否实现并可实际使用；从架构/代码、交付文件和实例操作发现bug、逻辑缺陷及改进机会，向负责人汇报结论和下一阶段建议。

## 已确认的实现信息

项目已有Electron、React/TypeScript、CesiumJS和SQLite WASM实现、安装包、自测记录与已知问题。原计划Tauri/Rust是建议，不用技术栈名称否决当前功能；检查实际职责划分、数据流、存储和绘图逻辑即可。

实现报告不是独立验收结论。现有安装/性能/界面证据可帮助定位，但新Agent需实际复现关键功能，不能照抄通过状态。本次计划Agent只更新文档和交付提示词，没有执行完整产品验收。

## 通过规则

基本的新增→保存→地图→编辑→重启→备份恢复闭环可用，无正常使用数据丢失、反复崩溃或核心功能失效即可判基本通过。其余功能尽量检查，P2/P3、理想性能差距和未测高级矩阵公开记录，安排后续迭代。

详细规则与AC清单见07_ACCEPTANCE.md。已撤出的审查要求不参与结果判定，旧报告中因地图边界资源不足而产生的阻断结论不再适用本轮；旧事实和证据不改写。

## 保留的功能定位

- 航班由用户手填，不核实真实航班/航迹。
- 本地参考资料可用且允许自定义，不要求全球全集。
- 地球自由操作，路线根据已有坐标生成，缺坐标可补。
- 英语UI、侧栏、Logo和样式设置有真实入口。
- 数据持久化与备份恢复正常，个人覆盖不被静默改写。

## 后续建议的组织

报告分别列：需修复的核心bug、非阻断功能不足、视觉/交互/性能提升、维护性改进和可选增强。每项指出收益、优先级与复测条件，版本编号由负责人以后决定，不在验收中自动升级。
