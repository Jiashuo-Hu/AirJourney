# 05 · 数据、Logo、地图与字体资源策略

状态：已失效旧稿（未编号） · 核验日期：2026-10-10 · 本次仅调查来源与规划采集，不宣称已获得全部资源。

## 1. 三类“标准”分别处理

航空代码：IATA 航空公司/机场标识以及 ICAO 航空公司/机场/机型标识。地理数据：机场坐标及对应坐标基准、IANA 时区。地图表达：中国内地适用的国界、行政区界、地域名称及审图要求。ISO 或社区 country code 只作为外部对照标识，不能直接决定最终 UI 地域分类。

IATA 是其代码的官方维护方，官方数据库与社区整理资源的授权和准确性不同。[IATA 官方目录](https://www.iata.org/acd)。无需假设“采用 IATA 格式”就代表已获得官方全量数据库许可。

## 2. 航空目录获取

| 数据 | 首选/补充 | 实现策略 | 不能做的承诺 |
| --- | --- | --- | --- |
| 机场坐标、名称、代码候选 | OurAirports；关键字段以官方机场/航空资料核验 | 固定快照、检查字段、排除城市/车站代码；记录源版本 | 不称社区数据是 IATA 官方数据库 |
| 官方航空公司代码 | 授权 IATA/ICAO 数据；航空公司官网作为核验补充 | 先调查成本与再分发条款，保留证据 | 不抓取受限数据库并随包再分发 |
| 航司联盟关系 | 三大联盟官方名单、公告与航司公告 | 当前关系与历史 effective interval 分开 | 不从代码共享伙伴列表推定正式会员 |
| 机型 | ICAO Doc 8643/制造商资料，核验使用条件 | 型号/系列区分；无证据时不填官方 type code | 不把产品家族和精确变体混为一谈 |
| 时区 | IANA tzdb + 有来源的机场映射 | 单机场核验，记录映射和 tzdb 版本 | 不按经度整数或国家唯一时区猜测 |

[OurAirports](https://ourairports.com/data/) 提供公开数据，但不保证准确性；因此可用作启动目录，正式支持机场需至少核验标识、经纬度、英语名称和时区。不要直接继承其 countries 表作为中国内地标准的地图/地区表达。

## 3. 目录覆盖与验收边界

用户期望全球可扩展的航空目录与完整品牌体验。正式 旧稿 目标不是只硬编码几个常见航司，而是定义有清单、有版本、可扩展的 Supported catalog。

- 机场目标：覆盖来源快照中有有效标识的在营民航客运机场；历史/停运机场保留检索入口，明确状态。无 IATA 但有核验 ICAO 的机场可支持。
- 航司目标：全球在营定期客运承运人目录；停运历史航司逐步补充，允许 Custom 记录防止用户被阻塞。
- 每个正式支持机场具备核验坐标和时区；每个正式支持航司具备核验代码状态、联盟状态及合格 SVG Logo。联盟关系未知可以如实标为 Unknown，不可以猜测。
- 用户目录外航司可用 Custom 录入，临时字母占位需明确；它不满足“正式支持航司有矢量 Logo”的验收。
- Logo 全局覆盖可能涉及大量人工授权核验。P0 必须交付源目录总数、纳入数、排除理由、待补数和比例；数量不能在本计划中凭空给出。
- 若全量 Logo 无法取得，提出具体分批覆盖方案并由负责人决定。未经决定，缩小支持清单来制造 100% 覆盖不得视作完全满足原始需求。

首批资源检验样本建议包含中国内地、港澳台、欧洲、北美、亚洲其他地区、中东和无联盟航司；包括 Air China、China Eastern、China Southern、Cathay Pacific、Lufthansa、Singapore Airlines、ANA、United、American、British Airways、Qatar Airways、Emirates 等。此处仅用于验证流程，不是最终全量目录，也不是对这些航司当前联盟状态的断言。

## 4. 航空联盟历史

三大联盟：Star Alliance、SkyTeam、oneworld。成员名单优先官方主页及成员/新闻页面；暂停、拟加入、正式加入、退出、合作伙伴分别存状态和证据。

[oneworld 官方成员页](https://www.oneworld.com/members) 和 [SkyTeam 官方成员页](https://www.skyteam.com/en/about/our-members/) 是核验入口；Star Alliance 成员入口需要实现时重新访问核对，不使用搜索结果里的 codeshare 页面替代。

存储 valid_from/to（日期，可未知）、status、source_url、verified_at。只有核验日期而无历史生效日期时，不据此倒推历史。联盟官网更新后，当前标注可变；已经保存的飞行时结果快照不无提示改写。

不把“没有查到”显示为 No alliance；Unknown 与已核验无联盟分开。成员关系以实际承运航司为主，marketing 航司的信息显示在单独区域。

## 5. Logo 采集与许可

来源顺序：航司/联盟官方品牌或媒体中心 → 明确开放许可的 Wikimedia Commons 单文件页面 → 其他有可验证版权授权的资源库。Commons 是候选来源，不是品牌使用许可的 blanket approval。[Commons 许可说明](https://commons.wikimedia.org/wiki/Commons:Licensing)。

每个 asset 必须记录：entity_id、品牌英语名、文件名、来源页面、原文件 URL、作者、许可名称与链接、归属文本、商标说明、有效品牌时期、检索日期、源 revision、SHA-256、修改记录、授权审核状态。模板在 templates/asset_registry.csv。

“高清矢量”验收含义：SVG 的真实 path/shape/text vector 内容；完整 viewBox；没有把 PNG/JPEG base64 包装进 SVG；离线 24/48/96 px 及高 DPI 仍清楚。字体依赖要检查，有必要转曲且保留许可条件。EPS/PDF 只有许可允许转换时才转为 SVG。不能自动描摹照片 Logo 当成官方矢量资源。

安全净化去掉脚本、外链、事件属性和危险嵌入，不改变标志形状/品牌配色。保留原始来源文件与用于分发的净化版本 hash。不同主题使用批准的官方深/浅版本或中性底板，不任意重画。

版权许可与商标使用分开审核。所谓“开源网站可下载”不代表标志属于开源软件或自由商标。不能从品牌官网拿到图片就写“可自由再分发”。证据不足记 Needs review，后续不得当作已核验资源打包正式发布。

机场不要求为每一个机场采集品牌 Logo；用户原始要求明确航司与联盟 Logo。App 自有 Logo 和通用图标属于独立资产，不复制他人品牌。

## 6. 地图与地形策略

CesiumJS 是渲染工具，影像、地形、边界、文字标注、服务权限与缓存许可均独立。代码开源不等于地图数据开放；[Cesium 数据使用与归属指南](https://cesium.com/learn/ion/content-usage-and-attribution-guide/) 是授权调查入口。

推荐拆成可替换图层：基础影像/自然色、地形、国界/行政边界、英语地名、机场点、旅程线。若底图本身已经烧录了不符合目标要求的边界/标签，不能只叠加另一条线来遮盖冲突。

| 方案 | 角色 | 必须核验 |
| --- | --- | --- |
| 有权提供大陆标准内容的地图/测绘供应商 | 最终生产候选优先 | 全球覆盖、合法英语标注、Cesium 兼容、审图/展示条件、预算 |
| 天地图服务 | 可行性调查候选，不直接冻结 | token、HTTPS、客户端 origin、WMTS/坐标、全球和地形覆盖、缓存和分发条件 |
| Cesium ion 地形/影像 | 技术实验与生产备选 | 计划额度、第三方内容限制、中国网络可达性及地图表达 |
| 授权本地低分辨率自然色影像 + 自有合规标签层 | 离线降级候选 | 底图不得隐藏不一致标签；数据使用、制作/审核要求与最终表达 |

自然资源部标准地图服务作为边界表达核验参考，并非自动可直接转换成 3D 运行时瓦片的生产数据包。本次标准地图/天地图开发站访问未成功，具体服务接口和条款仍待 P0 核验；不宣称已批准。

[地图管理条例](https://big5.www.gov.cn/gate/big5/www.gov.cn/gongbao/content/2016/content_2979707.htm) 对向社会公开的地图及互联网地图服务有规定。个人本地原型、公开演示、安装包分发和线上服务的适用范围需要按实际方式核验，不能由本计划推定全部豁免或全部必须自行申请。对于拟公开发布，需确定供应商授权、成图审核和审图号等是否适用，必要时咨询供应商/主管部门。

本项目特定发布规则：未核验的全球社区边界不能成为“已符合内地标准”的默认发布底图。国界、港澳台、南海及其他争议区域的表达按有效权威依据核对；英文名称和地域归属使用有版本的 display policy，不让代码库/社区数据决定政治地理口径。

所有缩放级别、主题、离线底图、截图出口（若以后开放）都要检查同一表达规则。直接用地图已有审图号不能证明自定义 3D 组合/修改后的地图也获审核，必须核验供应商规定。

## 7. 坐标一致性

机场与航线逻辑使用 WGS84；每个地图源声明其 CRS、瓦片矩阵、投影、经纬度轴序和高度基准。CGCS2000、GCJ-02、BD-09 等不得默认为可直接互换；只通过许可允许且经验证的方法转换。若地图层与机场偏移，禁止用手动微移几个机场掩盖全局问题。

至少抽样 PEK、PVG、CAN、HKG、TPE、LHR、JFK、LAX、SYD、AKL，检查机场点与真实位置、反子午线和极区路线。坐标数值源误差与渲染误差分别报告。

## 8. 字体与其他资源

[Apple 字体许可](https://developer.apple.com/fonts/) 不作为 Windows 打包 San Francisco 的授权依据；除非以后取得相应书面许可，否则默认禁止复制/打包 SF 字体。采用 [Inter 官方仓库](https://github.com/rsms/inter) 中固定版本与 OFL 许可文件。Segoe UI 作为系统 fallback，不随包复制系统字体。

通用 SVG 图标、地图自然色纹理、地形、飞机图形同样记台账。App 的 Asset coverage 页面或第三方信息页显示许可、来源和更新日期；完整许可可在安装包的 notices 中查看。

## 9. 更新与费用

参考目录建议每季度核验；影响联盟/代码的重要官方变更可单独更新。更新时间不是准确性的保证。每个更新包记录版本、来源、hash、计数和变更；失败回到旧目录，不更改既存航班快照。
