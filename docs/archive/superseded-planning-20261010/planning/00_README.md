# AirJourney 计划与交付文档

状态：已失效旧稿（未编号） · 日期：2026-10-10（Asia/Shanghai）· 作者角色：计划 Agent

AirJourney 是个人飞行旅程记录 Windows App。核心体验：在左侧管理自己的航班，在右侧可交互的三维地球上回顾所有旅程。文档使用中文；App 的产品文案、菜单、表单、错误消息、无障碍名称及默认数据展示使用英语。用户自己输入的备注不限制语言。

本目录只交付规划文档、规格和验收模板，未创建应用代码、脚手架、真实航空数据库、地图数据或 Logo 文件。项目根目录为 `C:/MyFile/Project/AirJourney`。运行时个人数据另存用户应用数据目录，不能存入项目根目录或安装目录。

## 当前方案

建议采用 Tauri 2 + React + TypeScript + CesiumJS + Rust/SQLite。它是计划阶段的工程建议，必须通过 P0 的 Windows 三维渲染和地图数据适配验证才能冻结。桌面视觉参考 ChatGPT Windows 与 Apple 的留白、层级和简洁感；无需调用这两款产品的接口或复制其专有资源。

必须保持的四项结果：

1. 标准化的航空公司、机场、机型和时间录入，以及航空联盟关联。
2. 三维地球、陆地海洋和地形视觉、全部旅程航线，以及符合中国内地要求的地图表达。
3. 左侧航班管理、右侧地球、侧栏隐藏及恢复。
4. 航空公司和联盟的真实矢量 Logo，以及清晰精致的无衬线排版。

Apple Maps 是观感参照，不是地图数据来源或像素级复刻承诺。San Francisco 不作为默认 Windows 分发字体，采用 Inter 并保留许可。航线默认是端点间的地理示意弧线，不能标为真实飞行轨迹。

## 状态与权责

- 这是一份可执行的初始基线，并非已经获得项目负责人逐条批准的最终产品规格。文档新增的默认选择均见 09 文档。
- 实现 Agent 负责代码、资源采集、构建、运行验证与实现说明；验收 Agent 负责独立复现、逐项检查及结果报告。计划 Agent 本次职责止于这套文档。
- 预算、商业地图账号、Logo 的最终覆盖目录及公开发布方式尚未确认；不影响开始本地数据层、交互与可行性验证。
- 所有地图供应商、授权和国界表达未经验证前，不能把候选方案写成已符合中国内地标准。地图验证失败时可以继续其他模块，但最终完整旧稿范围 不可被判定通过。
- 任何范围缩减、技术替换或付费承诺应记录决策；改变用户四项核心要求须由项目负责人决定。

## 交付规则

功能 ID 使用 FR，业务规则使用 BR，质量要求使用 NFR；验收 ID 使用 AC。执行追踪表连接需求、实现证据和验收结果。每个阶段可提交部分成果，最终旧稿范围 必须满足全部 Must 项。占位 Logo、合成航线和无授权地图都不能冒充最终资源。
