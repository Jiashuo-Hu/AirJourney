# 06 · 实现分阶段计划

状态：已失效旧稿（未编号） · 依赖顺序优先于日历。预计约 20–35 个有效工作日可完成技术与产品实现；全球 Logo 授权、地图来源/审核和返工可能额外延长，不能把 Agent 的运行速度当成确定工期。

## P0 · 高风险可行性与资源调查（建议 3–5 日，不含外部审批）

任务：

1. 阅读全部计划，创建自己的实现记录与需求追踪表，不改写计划需求来迁就实现。
2. 在 Windows 11 x64 原型中验证 Tauri/WebView2/Cesium 的地球、资源路径、GPU、窗口 resize、DPI 和释放内存；构建真实安装包验证，不能止于开发服务器。
3. 对地图候选调查全球影像、真实地形、英语标注、中国内地标准、坐标兼容、许可/费用、网络可用性、缓存/离线规定和归属要求。
4. 用至少 12 家跨地区航司及三大联盟验证 SVG 获取、净化、许可登记和展示；提交全量目录覆盖估计和实际缺口。
5. 验证 IANA 时间、对跖点距离算法、SQLite 一致备份和 Windows 测试路径。
6. 提交 3 张视觉方向稿/截图：空状态、航班列表+地球、编辑表单，包含浅/深色布局。不得因等待可选审美反馈阻断其他已授权任务。

交付：`docs/implementation/feasibility.md`、provider_matrix、catalog_coverage、成本与许可清单、技术版本锁定提案、真实机器指标、地图表达核验记录。

阶段门：地球基本技术通过即可开始 P1；最终地图候选尚未核验时可以继续 P1/P2，但 P3 的正式数据配置和完整旧稿范围 发布验收保持未完成。若 Tauri 失败，提供 Electron/WinUI 备选验证。若无合法地图或 Logo 来源，不伪造完成，具体说明缺失和负责人需要的决策。

## P1 · 数据与领域核心（建议 4–6 日）

实现目录导入/校验、稳定实体 ID、历史代码与联盟模型、机场时区映射、机型 Unknown、飞行数据/快照、SQLite 迁移、时间转换、距离计算与统计。

交付：数据库 schema/迁移说明、reference data manifest、command 契约、领域测试、边界数据集。开发用样例必须明确 Synthetic。

阶段门：两端当地时间→UTC 正确；DST 两类异常处理明确；数据重启保留；历史快照不受目录更新影响；事务/迁移失败可恢复。数据库采用最终运行时路径。

## P2 · 航班管理与设计系统（建议 4–6 日）

实现英语 UI、主题/Inter、可调隐藏侧栏、增删改查、回收站、搜索/筛选、机型和距离录入、警告/错误、基本统计及键盘操作。

交付：实际界面截图/录屏、状态矩阵、交互测试和英语字符串清单。

阶段门：用户能够录入、编辑、删除/恢复一条航班；焦点/取消编辑正确；列表/统计同口径；高 DPI 关键控件可操作；无示例数据混入真实空库。

## P3 · 正式地球与路线联动（建议 4–7 日）

集成经核验的影像、地形、边界和地名配置；绘制曲线与机场；点击双向选择、重复路线聚合、总览/单段适配；跨日期变更线/极区/同机场处理；资源 attribution、map status、离线降级、GPU 错误。

交付：地图来源及图层清单、表达核验截图、路线测试、性能记录、全部正式支持品牌 SVG 台账。

阶段门：所有当前筛选有效航段可追溯地映射到路线/聚合组；没有假真实轨迹；视图移动连续且不漏线；地图表达与资产覆盖阻断项已清除。未解决时标为 Partial，不允许靠隐藏有问题的地区/航司通过。

## P4 · 备份、安全与分发（建议 3–5 日）

实现 JSON 备份/恢复预览、冲突决策、CSV 导出、防公式注入、迁移副本、错误日志、设置/来源页面、安装包与 WebView2 部署。审查 token、capabilities、CSP、SVG 安全和日志脱敏。

交付：installer + SHA-256、构建/安装说明、数据恢复说明、许可 notices、测试报告、实际签名状态与已知问题。

阶段门：干净机器安装运行、重启数据正确、导出/恢复逐字段一致、断网不丢数据、损坏/磁盘失败可诊断、卸载不默认清除个人记录。

## P5 · 独立验收与修复（建议 2–6 日，取决于缺陷）

实现 Agent 提交 candidate，第三个 Agent 按 07 独立验收。验收 Agent 发现问题不直接修改产品；回交实现 Agent 修复，生成新 build。每个新 build 重新跑失败项及受影响回归。合格后负责人决定使用/发布。

## 任务依赖

| 任务 | 依赖 | 可与之并行的工作 |
| --- | --- | --- |
| 时间/领域核心 | 需求基线与数据结构 | Logo/地图调查 |
| 表单 UI | command 草约 | 图层可行性实验 |
| 正式地图 | 图层许可、坐标和表达核验 | 备份导出 |
| 路线联动 | 记录 DTO 与 Cesium 验证 | 英语文案/DPI |
| 数据恢复 | 数据 schema、快照约定 | 安装流程 |
| 验收 | 安装包、覆盖表、实现证据 | 不应边验收边静默修改 build |

此处“并行”描述任务调度，不授权自动创建更多 Agent。用户指定三个角色：计划、实现、验收。

## 完成定义

每项功能完成需要代码/资源、必要自动测试、真实运行证据、更新追踪表和已知限制。整体完成还需要所有 Must 通过独立验收，以及地图/品牌授权事实核验；本地原型能展示不等于完整旧稿范围 已完成。

实现 Agent 的阶段更新应以已验证结果、剩余不确定性和下一步为主，禁止把尚未下载的 Logo、候选地图服务或没测的性能描述为完成。

## 变更控制

新增需求记 CR：原因、受影响 FR/BR/NFR、代价、验收变化和负责人决定。实现细节可由实现 Agent 自主处理；缩小原始四项范围、付费采购、公开发布、增加默认云上传须由负责人明确决定。技术栈变更不自动改变产品要求。
