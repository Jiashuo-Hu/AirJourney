## 架构与逻辑核验

| 模块 | 职责与核验结论 |
| --- | --- |
| App.tsx | 记录状态、编辑草稿、选择/筛选/统计、保存队列、导入。成功落盘后再更新已保存状态；失败保留草稿。队列串行写入不等于状态合并，见 AF-03。 |
| FlightEditor.tsx / Settings.tsx / Library.tsx | 分别负责航班输入、外观/单位、四类资料及导入预览。主职责清楚；精度、标签、预览类别存在局部状态问题。 |
| domain.ts / library-csv.ts | 校验、日期/时区、距离/路径、格式转换。正常时区与独立预期值一致，未知值保留；扩展 DST/极端输入未完整验证。 |
| storage.ts / preload.cjs / main.cjs | 备份资产/状态及受控存储桥接；SQLite 保存整份 JSON 状态。主进程复制数据库、事务更新、pending 写入和同步、保留 previous 后替换。正常保存/重启/恢复成功，既有失败写入用例本轮复跑通过；未证明所有断电窗口恢复。 |
| Globe.tsx | 单实例 CesiumWidget、本地底图、机场/聚合路线实体、选择与相机。实际渲染、旋转、缩放、列表/地图联动有效。复杂大量路线和长时运行未测。 |

记录保留资料快照，资料编辑默认影响未来选择，明确应用到历史记录才更新快照；本轮复跑两条路径，结果符合设计。个人 SVG 被包含在状态/备份，空库恢复后仍存在。以单一 JSON 状态保存符合当前个人规模；后续重点是避免旧快照覆盖新的独立操作，不需要本轮引入复杂存储架构。

## 执行与结果

1. **自动测试和构建**：重新运行 npm test，14/14 通过；TypeScript + Vite 构建通过，1369 模块。约 4.81 MB 主 JS 包的分块提示为维护/启动优化项，不是功能失败。
2. **实际新增/编辑/重启**：原生窗口新增 ACC-MANUAL-01，选择 PEK/LHR、未知时间保存，地图出现约 8176 km 路线；编辑编号为 ACC-MANUAL-01-EDIT，隐藏恢复侧栏仍保留草稿，保存、关闭进程、重启后 SQLite 中编号一致。
3. **时间与距离**：输入 PEK 2024-01-15 10:00 UTC+08 → LHR 同日 14:00 UTC+00，派生 720 分钟；人工 735 分钟另行保留。输入 1000 miles，显示 1609.3 km，原始 1000/miles 未被改写。Unknown、日期-only、缺坐标记录可保存，补坐标后路线出现。同点记录距离零且有环形呈现。
4. **目录与定制**：四类资料分别新增、编辑、隐藏、恢复成功；默认/None 人工选择可保存。四种个人字段及改类型归档原值成功。已有 LH SVG 与未知占位可显示；真实文件对话框导入个人 SVG、保存显示、移除成功。存在标签输入、精度选择及导入跨页缺陷。
5. **地图与交互**：原生拖动地球、侧栏与快捷键操作通过；重新执行 packaged smoke 验证缩放/Reset、机场选中→列表与相机、聚合路线、草稿、地图选点确认、1024×720 无文档横向溢出。英语主要界面、字体与主按钮可用。详细排序/复杂筛选矩阵和所有图层组合没有穷尽。
6. **数据闭环**：中文备注搜索、无匹配结果、状态筛选同步影响列表与 mapped 数量；复制生成独立 UUID；回收站恢复的记录逐字段一致；明确永久删除只移除测试副本。主题、单位、标签开关经渲染器重新载入保留，路线宽度保存成功。
7. **真实备份**：通过原生保存/打开对话框导出 `data/native-export.airjourney`，正常恢复与导出前全状态深比较一致；再启动独立空用户目录恢复，2 条航班、个人资料、SVG 和设置全状态一致。冲突预览后取消全状态不变；普通错误文件未改库；CSV 导出含中文、多行/引号备注、原输入与派生值。错误 toast 未截获，不把截图当作错误文案证据。
8. **补充响应观察**：1000 条构造记录、30 次查询 P95 63.9 ms、30 次存储提交 P95 34 ms、5 秒交互帧率中位数约 59.5 FPS。存储指标不是完整“点击保存到地图更新”耗时，不能外推到低配设备或长时运行。

既有 packaged smoke 本轮 16/16 通过、无记录的 renderer error，其中一项 CSP 断言是套件自带，不据此展开或宣称通过安全验收。独立测试阶段 2 有 6 个通过项，阶段 3 有 6 个通过项；阶段 1 包含两个“成功观察缺陷”的 PASS 标签，实际产品子项按执行表记 FAIL，不能将脚本 PASS 数量当成产品全通过率。
